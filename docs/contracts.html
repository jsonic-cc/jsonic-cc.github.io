Contracts

Correctness is expressed as behavior that must remain true.

Jsonic++ treats parser rules as contracts: valid JSON should parse consistently, invalid JSON should fail deterministically, errors should remain useful, and serialization should preserve the represented value.

Contract-first development: define the guarantee, prove that it can be checked simply, add executable evidence, then change the parser.

Core behavioral contracts

  • Reject malformed JSON rather than attempting permissive JavaScript-style recovery.
  • Reject duplicate object keys instead of choosing an implicit winner.
  • Validate JSON number grammar and finite numeric range.
  • Validate string escapes and UTF-16 surrogate pairs.
  • Report parse failures with line/column context.
  • Round-trip represented values through serialization.
  • Keep synchronized vendor copies byte-identical where the integration model requires it.

Why contracts matter

A parser can appear correct across hundreds of ordinary fixtures while still accepting one dangerous malformed family. The test suite therefore needs both positive examples and adversarial neighbors designed to falsify each guarantee.
