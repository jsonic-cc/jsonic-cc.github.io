Battle tested

Test the grammar, then attack the boundaries.

Jsonic++ begins with unusual inherited evidence: the same parser implementation was already exercised inside Nift's configuration, tracking, project-contract, schema and parser workflows, and inside Minify++'s JSON handling. Standalone ownership lets that evidence become parser-specific rather than incidental.

Current status: extracted and independently testable.The initial standalone checkpoint preserves the already-used implementation and adds dedicated smoke and adversarial tests; both suites also pass the current AddressSanitizer/UndefinedBehaviorSanitizer target with leak detection enabled. External conformance/fuzz campaigns should continue to expand this evidence.

What the retained tests attack

  • duplicate keys and malformed object/array structure
  • JSON number grammar and overflow/range rejection
  • escape sequences and Unicode surrogate handling
  • raw control characters in strings
  • nested arrays/objects and serialization round trips
  • named-array streaming and duplicate root members
  • consumer synchronization with Nift and Minify++

Memory safety

The repository includes an AddressSanitizer/UndefinedBehaviorSanitizer target with leak detection enabled. Passing sanitizer workloads is evidence for those workloads—not a timeless proof that arbitrary future code cannot contain a lifetime bug.

What comes next

JSONTestSuite-style conformance corpora, coverage-guided fuzzing, sanitizer repetition and parser differential testing against mature implementations are natural next evidence layers. When those runs happen, preserve exact corpus/tool versions and results rather than converting them into vague marketing claims.
