Architecture

The small shape is part of the design.

Jsonic++ keeps parsing, the value model and serialization in one auditable header. There is no runtime library to link and no plugin or allocator framework to configure.

Ownership

json::Document owns its strings, arrays and object members through ordinary standard-library containers. Objects preserve member insertion order while duplicate keys are rejected during parsing.

Parser boundary

The parser accepts JSON grammar, not JavaScript object literals. It rejects trailing commas, duplicate keys, malformed numbers, invalid escapes, unpaired UTF-16 surrogates and non-finite/out-of-range number forms encountered by the current implementation.

Vendoring

Standalone Jsonic++ owns parser semantics. Nift and Minify++ own their integration behavior around synchronized copies. That boundary allows the parser to remain dependency-free without letting vendored copies silently fork.
